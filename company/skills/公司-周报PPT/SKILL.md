# 周报（先了解，再照部门的做法做）

每个部门的周报都不一样：有的以数字表格为主（金额、数量、达成率），有的以文字为主（项目进展、出差情况、问题与计划），
有的是把几个人的周报汇总成一份。**不要套用固定格式，先弄清这个部门现在怎么做。**

部门的做法记在 `~/<部门>/05_模板/周报说明.md`（没有就是还没设置过）。

## 情况 A：还没有 `05_模板/周报说明.md` —— 先了解
1. 请用户把 **1~2 期往期周报** 放进 `05_模板/`（PPT、Word、Excel、PDF 都可以），再说明本周的原始材料放在哪里。
2. 读样本（只看结构，不要整篇贴进对话）：
   - Word / PPT / PDF：`markitdown 文件 | head -150`（PDF 也可以 `pdftotext -layout 文件 - | head -150`）
   - Excel / CSV：`python3 /opt/company/kit/peek.py 文件`
3. 把你的理解整理给用户确认，逐项问清：
   - 汇报对象；一共几页 / 几部分，每部分写什么
   - 数据和材料从哪里来（哪些文件、谁提供、每周什么时候放进 01_原始数据）
   - 哪些数字要算、口径是什么（求和/计数/占比、筛选条件、单位）、跟上周或目标怎么比
   - 哪些内容是文字（项目进展、问题、计划），是照抄、摘要还是汇总多人的
   - 图表要哪些；交付只要 PDF，还是另附 Excel 明细
4. 用户确认后，写成 `05_模板/周报说明.md`（用中文、分条写清上面每一项，附样本文件名），以后每周按它做。
   用户以后要改做法，就改这个文件。

## 情况 B：已有 `05_模板/周报说明.md` —— 每周照做
1. 读 `05_模板/周报说明.md`（`dept.py start` 会同时列出部门说明和配方；周报里的固定出数步骤可以存成配方，每周 `recipe-run`）。把本周周次、日期范围、要用的文件告诉用户，**缺材料先说，不要编**。
2. 数字：写 `script.py` 用代码算（口径按周报说明，写法见「公司-数据处理与出图」第 2 步，用 runio 记下结果摘要），出图用 `/opt/company/kit/charts.py`，明细表用 `tables.py`。
3. 文字：从原始材料里摘要，每条注明出自哪个文件 / 谁的周报；原文没有的内容不要补。
4. 做 PPT：按 `/opt/company/skills/pptx-generator/SKILL.md` 和 INDEX 第二节的公司规定，结构照周报说明；
   第 1 页后放「本周结论」（不超过 3 条，带数字）。
5. 转 PDF：`python3 /opt/company/office2pdf.py <pptx>`；再 `python3 /opt/company/stamp_internal.py <输出目录> -r`。
6. 输出放 `03_周报/<周次>/`（如 `03_周报/2026-W38/`），`script.py` 一起保存。
7. 回复：PDF 路径 + 3 条结论 + 存疑事项（缺的材料、口径没确认的地方）。

## 可选工具：数字表格型周报的固定出数脚本
如果某个部门的周报**以数字表格为主**（每周从同一类表格按日期统计指标、和上周比、画趋势），并且用户同意，
可以用 `/opt/company/kit/weekly.py` 把出数、出图、PPT 版式固定下来，你只写结论，结论里的数字会被自动校验：
- `draft --dept-dir <部门> --file 01_原始数据/<样本>` 生成配置草稿 → 和用户逐项确认 → `check` 试算
- 每周：`prepare` → 读 `03_周报/<周次>/facts.md` → 只改 `结论.json` → `render`
- 配置格式参考 `/opt/company/kit/周报配置.示例.json`；用了这个工具，要在周报说明.md 里写明。
文字为主的周报**不要**用它。
