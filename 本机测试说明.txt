AI 助手平台 · 本机测试说明
==================================================

一、这是什么
------------
在自己电脑上跑一套和 NAS 完全相同的平台（同版本镜像、同一份 docker-compose.yml），
改代码先在本机测，测好了一键同步到 NAS。
没有智谱 API key 时，费用闸门用「模拟模式」返回假回复，登录、部门权限、终端工具、
计费、限额拦截整条链路都能测。

本机专用的文件（都不会被同步到 NAS）：
  本机测试工具.bat          菜单工具，日常只用它
  docker-compose.local.yml  本机和 NAS 的差异（文件夹位置、数据位置、模拟模式）
  .env.local                本机配置（本机专用密钥、管理页密码）
  data-local\               本机测试数据（启动后自动生成）
  nas-sim\                  模拟 NAS 的四个部门共享文件夹（启动后自动生成）


二、第一次准备（只做一次，约 30-60 分钟）
----------------------------------------
1. 安装 Rancher Desktop（免费，可商用）
   官网 rancherdesktop.io → Download → Windows 版 .msi，需要管理员权限。
   安装过程会自动启用 WSL2，可能要求重启电脑。
2. 第一次打开时的设置：
   - Container Engine（容器引擎）选 dockerd (moby)   ← 必须选这个，不要选 containerd
   - Kubernetes 不勾选（用不到，省内存）
   等窗口左下角进度跑完、没有报错。
3. 内存：WSL 默认最多用电脑一半内存。平台最多占用约 6.5GB，
   电脑有 16GB 及以上不用改；少于 16GB 要在 %USERPROFILE%\.wslconfig 里写：
       [wsl2]
       memory=8GB
   保存后重启 Rancher Desktop。
4. 双击「本机测试工具.bat」→ 选 1 检查环境，看 Docker 是否就绪、ghcr.io 通不通。
5. 选 2 启动。第一次会下载约 6GB 镜像。
   下载失败 → 看第三节。


三、镜像下载不下来怎么办
------------------------
方法 A：换镜像站
   用记事本打开 .env.local，把 IMAGE_OPENWEBUI、IMAGE_TERMINAL 两行开头的
   ghcr.io 换成 ghcr.nju.edu.cn（可用性以实际为准），保存后再选 2。
   注意：版本号（v0.11.3 / 0.13.0）不要改，必须和 NAS 的 .env 一致。

方法 B：从 NAS 导出（NAS 上已经拉好镜像时用）
   1) DSM 控制面板 →「终端机和 SNMP」→ 勾选「启动 SSH 功能」
   2) 电脑 PowerShell：ssh 管理员账号@<NAS-IP> ，登录后执行：
        sudo docker save -o /volume1/docker/open-webui.tar ghcr.io/open-webui/open-webui:v0.11.3
        sudo docker save -o /volume1/docker/open-terminal.tar ghcr.io/open-webui/open-terminal:0.13.0
   3) 从 \\<NAS-IP>\docker 把两个 .tar 复制到本文件夹的「镜像」子文件夹
   4) 本机测试工具 → 选 7 导入 → 选 2 启动
   （方法 B 时 .env.local 里的镜像地址保持 ghcr.io 开头不要改）


四、日常改代码流程
------------------
  改了什么                        本机怎么生效                NAS 怎么生效（选 8 同步后）
  ------------------------------  --------------------------  ------------------------------------------
  cost-gate 里的 .py              菜单 3                      Container Manager → 容器 → ai-cost-gate → 重新启动
  company 文件夹（技能、脚本）    菜单 3                      ai-init-folders 启动一次，重启 ai-term-* 四个
  docker-compose.yml              菜单 2                      项目 → ai-platform → 停止 → 构建
  .env（端口、预算、镜像版本）    改 .env.local 后菜单 2      直接编辑 \\<NAS-IP>\docker\ai-platform\.env → 构建

同步规则（菜单 8）：
  - 先列出要复制的文件，输入 Y 才真正复制
  - 只增不删；NAS 上比本机新的文件会跳过
  - 永远不碰：NAS 的 data 文件夹、.env、部门共享文件夹

六、本机测不了、必须上 NAS 验证的
--------------------------------
  - 群晖共享文件夹的个人授权权限（本机 nas-sim 没有 ACL）
  - 真实智谱调用：回复质量、真实 usage 计价（本机也可测：.env.local 填 key 并把 GATE_MOCK 改 0）
  - NAS 4 核 8GB 下的速度和内存余量、多人同时使用
  - 局域网其他电脑访问 <NAS-IP>:8030
  - 定时任务长期运行


七、注意
--------
  - NAS 的 .env 里没有 GATE_MOCK，模拟模式在 NAS 上默认关闭；同步后确认 NAS 自检页顶部没有橙色条。
  - .env.local 的密钥是本机专用的，不要复制到 NAS。
  - 想从零重测：菜单 6 停止 → 删掉 data-local 和 nas-sim 两个文件夹 → 菜单 2。
  - 菜单 4 看日志时按 Ctrl+C 退出，问「终止批处理操作吗」时按 N 回到菜单。

十一、记忆与运行环境加固（2026-09-24，v1.9）
--------------------------------------------
  改了什么：
    记忆（助手「记住」的东西只放在部门说明里，并且管住它的大小和质量）
    1 部门说明加上限和复核（company\kit\dept.py）
        - 篇幅上限约 3000 字（每次任务都要读，越长越费钱）：超了不再写入，先和用户合并/删除旧条目
        - 同名口径已存在（比如已有「入库金额 = …」又要记一条「入库金额 = …」）不写入，先问用户是不是改口径；
          确认后用 note --replace 改写
        - 新增 note-list（带编号列出）、note-del（删除）、note-review（记录复核日期）；
          改写和删除都记进 05_模板\部门说明_修改记录.md（可追溯）
        - 5 条以上且超过 31 天没复核、或快到上限时，助手会在任务最后提醒一次
        - 新快捷指令 /部门说明：助手列出全部条目，指出重复、过时、矛盾的，逐条确认后整理并记录复核
        - 月度价值页「部门说明」一列显示 条数 · 字数/上限 · 最近复核；需要整理的部门标黄，页面顶部有提示
    2 关掉 Open WebUI 自带的「个人记忆」（原版默认对员工开放，已实测确认）
        - 口径统一记在部门说明里：全部门共用、可复核；个人记忆会按人插进提示词，破坏缓存、增加费用
        - docker-compose.yml 加了三个开关（只对新数据库生效）；一键初始化会再强制关一次（对已有数据库生效），
          配置检查新增「平台开关」一栏，有人在界面上重新打开会被发现
    3 长对话提示（费用闸门 v1.4 + 过滤器 v1.2）
        - 本对话上一轮输入 ≥ 6 万 tokens，或费用 ≥ 单对话上限的 60%（¥3）时，对话上方显示提示：建议做完这一步开新对话
        - 同时请助手在本轮结束时先列「建议记入部门说明」，再建议开新对话（只影响发给模型的内容，不写进对话记录）
        - .env 可调：CHAT_HINT_TOKENS、CHAT_HINT_PCT（0 = 不提示）
    运行环境
    4 （v1.9.1 取消）进程数上限 pids_limit：NAS 内核不支持，启动时只会报警告，已从配置里去掉
    5 部门终端守护 company\term_guard.py（由 company\term_entry.sh 在终端启动时带起，镜像不用重建）
        - 助手执行的命令超过 20 分钟自动终止（连同子进程）；员工自己打开的终端面板不受影响
          （实测：Open Terminal 原版不会结束卡住的命令，只是不再等它）
        - 每小时清理 /tmp 下超过 24 小时的临时文件
        - 终止和清理都记在该终端容器的日志里
    6 工具输出截断（费用闸门）：单条命令输出或读文件超过 1.2 万字，只把开头 60% 和结尾 40% 发给模型，
      中间写明截掉了多少字；员工在界面上仍能看到全文（实测：Open WebUI 和 Open Terminal 原版都不截断，
      一次 print 大表格会把几万字塞进后面每一轮对话）。.env 可调 TOOL_OUTPUT_MAX_CHARS（0 = 不截断）
    7 单轮最多连续调用工具 50 次（Open WebUI 原版 256 次），防止模型在一轮里反复试错空转
    8 提示词里告诉助手这些限制（命令 20 分钟、输出 1.2 万字），让它主动拆步骤、把结果写文件
    9 回归测试 13 项（新增：部门说明冲突/上限/改写/删除/复核，终端守护终止超时命令与清理临时文件）；
      部门终端自检 12 项（新增：终端守护在运行）
  生效：

十二、让 Container Manager「停止 → 构建」可靠（2026-09-24，v1.9.1）
------------------------------------------------------------------
  起因：NAS 上项目点「停止」没反应、「构建」一直灰。查下来是之前一次重建中途失败，留下一批名字前面
        带编号的旧容器（如 a938b308f752_ai-open-webui），界面按名字找不到它们，停止就无效。
        重建失败最可能的原因：docker-compose.yml 里部门终端带着「构建镜像」的配置，
        NAS 点「构建」时会去外网下载软件重新做终端镜像，网络一卡就半途失败。
  改了什么：
    1 docker-compose.yml 去掉部门终端的 build 配置，改成 pull_policy: never（NAS 只用导入的镜像，不构建、不下载）；
      Open WebUI 镜像 pull_policy: missing（本机已有就不再联网拉取）
      → NAS 上「构建」只是按新配置重建容器，不依赖外网
    2 终端镜像的 build 配置挪到 docker-compose.local.yml（只在本机用；菜单 A 照常构建，用法不变）
    3 去掉 pids_limit（NAS 内核不支持，只会刷警告）；自检相应减为 12 项
  以后 NAS 上线固定流程（界面即可）：
    菜单 8 同步 → Container Manager → 项目 ai-platform → 停止 → 构建 → 管理页「一键初始化」
    要换终端镜像时：本机菜单 A 构建 → 菜单 B 导出 → NAS 映像「从文件添加」→ 项目 停止 → 构建
  界面万一又停不下来（容器名前面出现一串编号）：
    SSH → cd /volume1/docker/ai-platform → sudo docker compose down → sudo docker compose up -d
