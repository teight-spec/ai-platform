AI 助手平台 · 本机测试说明
==================================================

一、这是什么
------------
在自己电脑上跑一套和 NAS 完全相同的平台（同版本镜像、同一份 docker-compose.yml），
改代码先在本机测，测好了一键同步到 NAS。
没有智谱 API key 时，费用闸门用「模拟模式」返回假回复，登录、部门权限、终端工具、
计费、限额拦截整条链路都能测。

本机专用的文件（都不会被同步到 NAS）：
  本机测试工具.bat          菜单工具，日常只用它
  docker-compose.local.yml  本机和 NAS 的差异（文件夹位置、数据位置、模拟模式）
  .env.local                本机配置（本机专用密钥、管理页密码）
  data-local\               本机测试数据（启动后自动生成）
  nas-sim\                  模拟 NAS 的四个部门共享文件夹（启动后自动生成）


二、第一次准备（只做一次，约 30-60 分钟）
----------------------------------------
1. 安装 Rancher Desktop（免费，可商用）
   官网 rancherdesktop.io → Download → Windows 版 .msi，需要管理员权限。
   安装过程会自动启用 WSL2，可能要求重启电脑。
2. 第一次打开时的设置：
   - Container Engine（容器引擎）选 dockerd (moby)   ← 必须选这个，不要选 containerd
   - Kubernetes 不勾选（用不到，省内存）
   等窗口左下角进度跑完、没有报错。
3. 内存：WSL 默认最多用电脑一半内存。平台最多占用约 6.5GB，
   电脑有 16GB 及以上不用改；少于 16GB 要在 %USERPROFILE%\.wslconfig 里写：
       [wsl2]
       memory=8GB
   保存后重启 Rancher Desktop。
4. 双击「本机测试工具.bat」→ 选 1 检查环境，看 Docker 是否就绪、ghcr.io 通不通。
5. 选 2 启动。第一次会下载约 6GB 镜像。
   下载失败 → 看第三节。


三、镜像下载不下来怎么办
------------------------
方法 A：换镜像站
   用记事本打开 .env.local，把 IMAGE_OPENWEBUI、IMAGE_TERMINAL 两行开头的
   ghcr.io 换成 ghcr.nju.edu.cn（可用性以实际为准），保存后再选 2。
   注意：版本号（v0.11.3 / 0.13.0）不要改，必须和 NAS 的 .env 一致。

方法 B：从 NAS 导出（NAS 上已经拉好镜像时用）
   1) DSM 控制面板 →「终端机和 SNMP」→ 勾选「启动 SSH 功能」
   2) 电脑 PowerShell：ssh 管理员账号@<NAS-IP> ，登录后执行：
        sudo docker save -o /volume1/docker/open-webui.tar ghcr.io/open-webui/open-webui:v0.11.3
        sudo docker save -o /volume1/docker/open-terminal.tar ghcr.io/open-webui/open-terminal:0.13.0
   3) 从 \\<NAS-IP>\docker 把两个 .tar 复制到本文件夹的「镜像」子文件夹
   4) 本机测试工具 → 选 7 导入 → 选 2 启动
   （方法 B 时 .env.local 里的镜像地址保持 ghcr.io 开头不要改）


四、日常改代码流程
------------------
  改了什么                        本机怎么生效                NAS 怎么生效（选 8 同步后）
  ------------------------------  --------------------------  ------------------------------------------
  cost-gate 里的 .py              菜单 3                      Container Manager → 容器 → ai-cost-gate → 重新启动
  company 文件夹（技能、脚本）    菜单 3                      ai-init-folders 启动一次，重启 ai-term-* 四个
  docker-compose.yml              菜单 2                      项目 → ai-platform → 停止 → 构建
  .env（端口、预算、镜像版本）    改 .env.local 后菜单 2      直接编辑 \\<NAS-IP>\docker\ai-platform\.env → 构建

同步规则（菜单 8）：
  - 先列出要复制的文件，输入 Y 才真正复制
  - 只增不删；NAS 上比本机新的文件会跳过
  - 永远不碰：NAS 的 data 文件夹、.env、部门共享文件夹

模拟模式的回复规则（固定、可预期）：
  普通消息 → 回显消息字数、消息条数、可用工具
  #工具    → 列出本次请求带的工具和参数
  #调用 工具名 {JSON参数} → 模拟模型发起工具调用，终端真实执行，再显示返回结果


六、本机测不了、必须上 NAS 验证的
--------------------------------
  - 群晖共享文件夹的个人授权权限（本机 nas-sim 没有 ACL）
  - 真实智谱调用：回复质量、真实 usage 计价（本机也可测：.env.local 填 key 并把 GATE_MOCK 改 0）
  - NAS 4 核 8GB 下的速度和内存余量、多人同时使用
  - 局域网其他电脑访问 <NAS-IP>:8030
  - 定时任务长期运行


七、注意
--------
  - NAS 的 .env 里没有 GATE_MOCK，模拟模式在 NAS 上默认关闭；同步后确认 NAS 自检页顶部没有橙色条。
  - .env.local 的密钥是本机专用的，不要复制到 NAS。
  - 想从零重测：菜单 6 停止 → 删掉 data-local 和 nas-sim 两个文件夹 → 菜单 2。
  - 菜单 4 看日志时按 Ctrl+C 退出，问「终止批处理操作吗」时按 N 回到菜单。

八、办公版终端镜像（2026-09-22 新增：Excel/Word/PPT/PDF 开源技能）
------------------------------------------------------------------
  是什么：部门终端从原版 Open Terminal 换成「办公增强版」ai-term-office:1.1，
          补装 xlrd（读老 .xls）、pdfplumber（PDF 表格）、reportlab（生成 PDF / PDF 标注）、
          pptxgenjs（做 PPT）、markitdown、文泉驿字体 + 微软雅黑等字体替换表。
          开源技能放在 company\skills\（总目录 INDEX.md；来源和许可见「来源与许可.md」）。
  本机：  菜单 A 构建（第一次 5-15 分钟）→ 最后自动跑自检，8 项全部 [OK] 即可。
          之后照常用菜单 2/3；菜单 1 会显示办公版镜像有没有。
  NAS 两种办法（二选一）：
    ① 本机菜单 B 导出 镜像\ai-term-office_1.1.tar → NAS Container Manager → 映像 → 新增 → 从文件添加
    ② NAS 能上外网时，项目「构建」会按 term-image\Dockerfile 自动构建
    然后菜单 8 同步代码 → 项目 ai-platform → 停止 → 构建 → 管理页再点一次「一键初始化」（更新助手提示词）
    NAS 自检：Container Manager → 容器 ai-term-zc → 终端机 → 执行  sh /opt/company/selfcheck.sh
  验证用例（资材助手里真实对话，需真实智谱 key，模拟模式测不了模型行为）：
    1 上传一个 .xls（ERP 导出）→「汇总各物料金额，出 Excel」  → 能读、出 xlsx、列宽撑开
    2「把上面结果写成 Word 说明，带一张趋势图」             → docx 中文正常、图正常
    3「做 3 页 PPT 汇报」                                    → 只给 PDF；pptx 在「底稿」子文件夹
    4 上传一个带表格的 PDF →「提取表格成 Excel」             → 表格完整
    5 所有产出都有「内部文件，禁止外传」标注
