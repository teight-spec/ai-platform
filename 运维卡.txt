一、防误删：群晖快照（只做一次，约 10 分钟）
------------------------------------------
为什么：部门助手对本部门文件夹可读写，一条错误命令就可能删掉或改坏原始数据；
        快照相当于每小时给文件夹拍一张照片，只记录变化的部分，几乎不占空间，误删了能找回。
前提：存储空间是 Btrfs（DSM →「存储管理器」→ 存储空间 → 文件系统一栏可查看；ext4 没有快照，改用 Hyper Backup）。

1. DSM → 套件中心 → 搜索「Snapshot Replication」（快照复制）→ 安装
2. 打开 Snapshot Replication → 左侧「快照」→ 选中共享文件夹「AI资材」→ 上方「设置」
   - 「计划」：勾选「启用快照计划」，每天，每 1 小时（时间段可选 07:00~21:00）
   - 「保留策略」：选「高级保留策略」，按时保留 24 个、按天保留 14 个
     （= 最近一天每小时一个，最近两周每天一个；想省空间可改成按天 7 个）
   - 确定
3. 对「AI财务」「AI营销」「AI总裁办」「docker」四个文件夹重复第 2 步
   （docker 里有平台数据 ai-platform\data：员工账号、对话记录、费用记录）
4. 一小时后回来看：「快照」里每个文件夹都有快照列表，就算设置好了


二、误删 / 改坏了怎么恢复
------------------------
A. 找回一个或几个文件（最常用）
   Snapshot Replication →「快照」→ 选中文件夹 →「快照」→ 列表里选出事之前的时间点 →「浏览」
   → 在打开的 File Station 里找到文件 → 复制到原来的位置（或先复制到别处，核对后再替换）
B. 整个文件夹退回到某个时间点（慎用）
   同上选中时间点 →「恢复到此快照」。这个时间点之后的所有改动都会丢掉。
   做之前先点「拍摄快照」把现在的状态也存一张，万一恢复错了还能回来。
C. 平台数据（账号、对话、费用记录）坏了
   Container Manager → 项目 ai-platform → 停止 → 用 A 的办法把 docker\ai-platform\data 从快照里复制回来 → 启动


三、快照不等于备份（建议，按需）
------------------------------
快照和原文件在同一组硬盘上，硬盘阵列坏了会一起丢。
建议用「Hyper Backup」每周把四个 AI 文件夹和 docker\ai-platform\data 备份到 USB 硬盘或另一台机器。

五、改代码 / 升级的固定流程（不直接在 NAS 上改）
----------------------------------------------
1. 本机改代码 → 本机测试工具 菜单 3（重启）
2. 菜单 C（运行测试）：工具包回归 + 各部门配方回归，全部通过
3. 本机管理页「一键初始化」→ 每行绿勾 →「配置检查」显示完全一致
4. 菜单 8 同步到 NAS → 按《本机测试说明》第四节重启对应容器 → NAS 管理页「一键初始化」→ 自检页全绿
5. NAS 上也跑一次测试：Container Manager → 容器 ai-term-zc → 终端机 → python3 /opt/company/tests/test_kit.py
6. 需要上传 GitHub 时：跑脱敏导出脚本，再双击「推送到GitHub.bat」
升级 Open WebUI 版本：先只在本机 .env.local 改版本号 → 菜单 2 → 一键初始化（看有没有失败行）→ 配置检查 → 菜单 C；
全部正常再改 NAS 的 .env。升级最容易坏的是一键初始化（它调用 Open WebUI 的内部接口）。


六、内存够不够（上线后找一个多人同时用的时段测一次）
--------------------------------------------------
docker-compose 里的内存数字是「上限」不是「占用」：Open WebUI 2G、费用闸门 384M、四个终端各 1G，
空闲时实际占用小得多；风险在几个人同时转 PDF、跑大表格的高峰。NAS 上如果还跑着别的服务，也要一起算进去。
测法：电脑 PowerShell 执行 ssh 管理员账号@<NAS-IP> ，登录后执行
    sudo docker stats --no-stream --format "table {{.Name}}\t{{.MemUsage}}\t{{.CPUPerc}}"
    free -m
把结果记下来：日期时间、同时在用的人数、每个容器的内存、NAS 的 available（可用内存）。
判断：
  - NAS 可用内存长期低于 1GB，或某个终端经常接近 1GB 上限 → 调低不常用部门的终端上限，或提醒大任务错峰
  - 各容器都远低于上限 → 维持现状；以后加部门时按实测值估算还能加几个
